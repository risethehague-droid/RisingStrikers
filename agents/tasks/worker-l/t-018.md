## Goal
Luca, 25 Oct 06:56 ("super important"): "we need to rework the tackle animation and speed / feel, you can spam it too
easy, it should have more draw back if you miss so slower reset time, either through making the slide actually slide
more, but not too far either and gets up after, this will pace the game better".

Today (actions.js `slideTackle` / `slides`, `challenge`): the slide flies at 9.5 m/s, lasts 0.6 s (cool 0.7), then a
0.45 s get-up (0.25 if won) - you can slide again ~1 s after a miss. The standing CHALLENGE (pass button) has cool 0.6
and a 0.35-0.4 s stumble on a miss. Both are spammable.

**1. The slide:** it really slides along the grass - a bit further than now (aim ~3.5-4 m, not more), slowing
naturally - then he GETS UP. A miss costs ~1.3-1.5 s before he can do anything (slide + get-up + a beat). A won slide
gets up quicker (~0.3 s) and a block tackle keeps the ball as now. No queued presses: SHOOT while sliding / getting up
does nothing.
**2. The standing challenge:** a miss costs more (stumble ~0.6 s, can't challenge again for ~1 s). Mashing it doesn't
win more often than timing it.
**3. Same rules for the computer** (it shouldn't spam slides either); keep how often it tackles sensible - measure.
**4. Both paces** (Classic and Arcade). Fouls from slides stay as they are (ball first = fair).

Animation: the slide today has only 3 frames per direction. The taskmaster is making new PixelLab moves (batch 19: a
proper slide `slide2` and a get-up from it `slideup`, 8 directions). If they're in the kits' manifest when you start,
use them (contact frame = when the boot reaches the ball); if not, build the feel with the existing frames (`slide`,
`getup`) and keep the move names in ONE table so the new frames drop straight in. Never draw art in code.
