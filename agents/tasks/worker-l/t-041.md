Build:
1. `tools/lan/lantest.html`: one self-contained page (plain JS, no libraries, no build). Two buttons:
   - **HOST**: makes an RTCPeerConnection + data channel and shows the offer as a **join code** (the SDP once ICE

   - **JOIN**: paste the host's code; it shows its answer code to send back.
   - Connected: a status line (connected / failed + the ICE state), a "ping x20" button showing the round-trip

## Notes
- How real games do it: FIFA / EA FC and eFootball online, one machine hosts and the other sends inputs
  (host-authoritative). Sensible Soccer had a 2-PC cable link. Old LAN games used a host IP you typed in. The "join
  code" is the no-server version of that.
- The claude.ai page sandbox: it's an iframe on a separate origin with a strict CSP. CSP doesn't normally cover
  WebRTC, but the iframe might not allow it. That's exactly what the test is for, so don't work around it; report it.
- Chrome hides local IPs behind `.local` mDNS names; on one Wi-Fi that still connects. Some routers block it, which
  is why the STUN checkbox exists.
- Keep it small: one session. Report `done` with the RTT you saw locally.
