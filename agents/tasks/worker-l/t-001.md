## 1. Research (summarise in the plan, with sources)
- **Test case structure:** ID, title, purpose, setup / preconditions, steps, expected result, actual result,
  pass / fail, evidence (ISO/IEC/IEEE 29119-3 test documentation).
- **Test types:** smoke, functional, regression, soak, performance (the ISTQB glossary).
- **Permutations:** combinatorial / pairwise testing (NIST's combinatorial testing work). It covers combinations
  of factors (team, difficulty, Classic vs new AI, weather, time of day, camera distance, power, position, keeper
  position...) without running every single combination. Show how many runs a matrix will take before it runs.
- **Game test tools as UI models:** Unreal Engine's Automation tool (Session Frontend: test tree, filters, run
  selected, results with logs), Unity's Test Runner. Game QA bug reports: repro steps, severity / priority,
  version, seed.
- **Repeatability:** every run has a seed and can be replayed exactly. The game is deterministic under a seeded
  `Math.random`; see how the split check did it (seeded matches, same result every time).
- **Accessibility of the tool:** WCAG 2.2 AA (keyboard use, contrast, visible focus, never colour alone, plain
  language). Luca and the co-designer are beginners: every term gets a plain-words explanation.

## 3. Design (in the plan)
- **Start here:** a guided first run, presets ("Quick check before a PR", "Full regression", "Lob & chip",
  "Keepers", "Compare difficulty levels"), and a glossary / tooltip for every term.
- **Test catalogue:** browse, search and filter every test. Each one says in plain words what it checks and what
  should happen.
- **Runner:** run one test, a selection, a group or a preset. Seeded, repeat N times, speed control, live view,
  clear pass / fail (icon + text, not only colour).
- **Results and data:** the numbers behind every run (speeds, heights, distances, timings, outcome), run history,
  comparing two runs or two versions, export (CSV / JSON), and a "report a bug" button that writes repro steps and
  the seed.
- **Permutations:** a matrix builder (pick factors and values → pairwise or full grid), with the run count shown
  first and the results as a grid.
- **Every action:** trigger every move the game has. Collect the list from `actions.js`, `ball.js`, `specials.js`,
  `matchflow.js` and `penalties.js`.
- **Every animation:** a browser for every sprite sheet (all kits, keepers, referee, props, effects). Every
  animation in all 8 directions, frame by frame, with contact frames marked.
- **Keep:** every existing test with the same setup and the same seeded results, FREE PLAY, the cut scenes, Bug
  Watch review, saving tuning, the database writes, and `tools/grp.js` working headless.
- **Build stages:** cut the build into 2-4 pull requests, each small enough to review, with a rough size.
