## HQ suggestion: read GitHub live, not only at the 2-hourly check (from the co-designer)

Today a `friend/` PR is on GitHub the moment it's opened, but its Needs OK card only appears at the next scheduled
check (every 2 hours, 09:00-23:00). The same delay hits the agent meters (assigned / reported / reviewed) and the
PR previews from the earlier note.

**Suggestion:** let HQ read GitHub itself when Luca opens it, so the page is current to the minute:

- **Open PRs** (and each one's `Preview:` line) -> the Needs OK column, previews included.
- **The agents branch** (tasks, reports, reviews) -> the agent meters: Brief / Branch / PR / Report / Review /
  Needs OK / Merged, and Idle when an agent has no open task.
- **Branches** named `<agent>/t-NNN-...` -> "Branch" step on the meter, "In progress" on the board.

**How (for you to judge):** the page's `mcp` capability with a GitHub connector on Luca's account (it calls GitHub
as the viewer, no token in the page), polling every minute or two while the page is open. The scheduled check
keeps doing what only it can do: reviews, verdicts and moving cards. If no GitHub connector is available, the
fallback is simply running the check more often (hourly, or around the clock).

**Not needed from the co-designer's side:** his account only views HQ; nothing changes for him except that his
PRs show up sooner.
